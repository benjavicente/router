# Core changes for angular

Changes to core packages needed for the Angular adapter

> Note: This is generated by AI

## 1. Angular route scaffolding target

What: `router-generator` supports `target: 'angular'` and can scaffold Angular root, route, and lazy-route files using standalone `@Component` classes.

Why: Angular routes cannot use React/Solid component templates. The generator needs to emit `createFileRoute`, `createRootRoute`, and `createLazyFileRoute` files that return Angular component classes through `component: () => ComponentClass`.

Where: `packages/router-generator/src/config.ts`, `packages/router-generator/src/template.ts`, `packages/router-generator/tests/template.test.ts`

## 2. Configurable Angular package import paths

What: Angular generator/plugin paths use Angular-specific package names instead of hard-coded React/Solid defaults. The router package can be configured with `angularRouterPackage`, and Angular Start route-tree module augmentation can use `angularStartPackage`.

Why: The Angular adapter currently lives under experimental package names, so generated files and route-tree augmentations must import from `@benjavicente/angular-router-experimental` and `@benjavicente/angular-start-experimental` instead of non-existent or wrong package paths.

Where: `packages/router-generator/src/config.ts`, `packages/router-generator/src/generator.ts`, `packages/router-plugin/src/core/router-code-splitter-plugin.ts`, `packages/router-plugin/src/core/code-splitter/framework-options.ts`

## 3. Angular-aware code splitting transforms

What: Router code-splitting accepts Angular as a target framework and forwards the Angular router package into generator transforms.

Why: Code-split route components need rewritten imports such as `lazyRouteComponent` from the Angular router package. Without this, rebased plugin changes can fall back to the wrong framework package or fail type checks.

Where: `packages/router-plugin/src/core/code-splitter/compilers.ts`, `packages/router-plugin/src/core/code-splitter/plugins.ts`, `packages/router-plugin/tests/code-splitter.test.ts`

## 4. Start compiler package resolution

What: `start-plugin-core` resolves framework package names through shared helpers, with Angular mapped to `@benjavicente/angular-start-experimental` and `@benjavicente/angular-router-experimental`.

Why: Server functions imported from Angular Start must be transformed into RPC calls. If the compiler looks for `@benjavicente/angular-start`, Angular `createServerFn` calls remain uncompiled and client queries can resolve to `undefined`.

Where: `packages/start-plugin-core/src/frameworkPackages.ts`, `packages/start-plugin-core/src/start-compiler/config.ts`, `packages/start-plugin-core/src/start-compiler/handleCreateServerFn.ts`, `packages/start-plugin-core/tests/createServerFn/createServerFn.test.ts`

## 5. Unique Angular component selectors for generated routes

What: Generated Angular route components now use path-derived selectors such as `route-component-posts-id-detail`, `route-component-posts-index`, and `lazy-route-component-lazy`.

Why: Angular expects component selectors to be unique. Reusing `route-component` or `lazy-route-component` across generated route files causes editor/compiler diagnostics and can make route components ambiguous.

Where: `packages/router-generator/src/template.ts`, `packages/router-generator/src/generator.ts`, `packages/router-generator/tests/template.test.ts`, `examples/angular/start-basic-react-query/src/routes/*`

## 6. Generator transform dependencies

What: `router-generator` declares parser/transform dependencies needed by the built generator output.

Why: Angular Start examples run route generation through built packages. Missing runtime dependencies such as `recast` can prevent Vite from loading generator/plugin code in examples.

Where: `packages/router-generator/package.json`, `pnpm-lock.yaml`
